## Blocking finding: `cbp-gate` cross-check cannot pass

A clean export of CBP HEAD `fc81041` has no job named `cbp-gate` in any
workflow. CBE was run with:

```text
cbe enforce-no-bypass --manifest ... --source-root <clean CBP tree> \
  --package-type cbs --package-version v0.1.0 --workflows \
  --gate-job '^cbp-gate$' --strict
```

Observed:

```text
exit_code: 3
gate_status: FAIL
GATE_JOB_NOT_FOUND for all 7 CBP workflows
BYPASS_ATTEMPT in .github/workflows/e2e-payload.yml
```

The `e2e-payload.yml` hit is the intentional `continue-on-error: true` on the
hostile-input test step; it is a test fixture, not a skipped CBP gate. The
missing `cbp-gate` job is the primary reason the requested cross-gate check
cannot be completed.

This is not evidence that CBP's own gates are broken; it is evidence that the
requested CBE↔CBP cross-check contract has no matching CBP job. CBE behaves
fail-closed (`GATE_JOB_NOT_FOUND`), but a fail-closed “missing target” is not a
PASS.
